# HealthTrack 2.0 — Firebase Setup Guide

## Overview
This guide walks you through setting up Firebase for the HealthTrack 2.0 application. Firebase provides Authentication, Firestore (database), Cloud Messaging (push notifications), and Storage for the shared backend.

---

## 1. Create Firebase Project

### Step 1: Go to Firebase Console
1. Open https://console.firebase.google.com
2. Click **"Add project"**
3. Enter project name: `healthtrack-2-0` (or your preferred name)
4. Enable **Google Analytics** (recommended)
5. Click **"Create project"**

### Step 2: Enable Required Services

#### Authentication
1. Go to **Authentication** → **Sign-in method**
2. Enable **Email/Password**
3. Enable **Google** (optional - for social login)
   - Add authorized domain: your Netlify domain
   - Configure OAuth consent screen in Google Cloud Console
4. Optional: Enable **Phone** authentication (requires Blaze plan)

#### Firestore Database
1. Go to **Firestore Database** → **Create database**
2. Start in **Production mode** (we'll deploy rules)
3. Choose location closest to your users (e.g., `asia-south1` for India)
4. Click **Enable**

#### Cloud Messaging (FCM)
1. Go to **Cloud Messaging** (via gear icon → Project settings → Cloud Messaging)
2. Note down **Server key** (for legacy HTTP) - though we use Firebase Admin SDK
3. For web: Generate **Web Push certificates** (VAPID keys)
   - Copy the key pair for frontend config

#### Storage
1. Go to **Storage** → **Get started**
2. Start in **Production mode**
3. Choose same location as Firestore
3. Click **Done**

## 2. Configure Firestore Rules & Indexes

### Deploy Rules
```bash
# Install Firebase CLI
npm install -g firebase-tools

# Login
firebase login

# Initialize in project root
firebase init firestore

# Select your project
# Use firestore.rules and firestore.indexes.json from this folder

# Deploy rules
firebase deploy --only firestore:rules

# Deploy indexes
firebase deploy --only firestore:indexes
```

### Storage Rules
```bash
firebase init storage
# Select storage.rules from this folder
firebase deploy --only storage
```

## 3. Get Configuration Keys

### Web App (for website & Flutter web)
1. Project Settings → General → **Your apps** → **Add Web App** (`</>`)
2. Register app name: "HealthTrack Web"
3. Enable **Firebase Hosting** (optional)
4. Copy the `firebaseConfig` object

### Android App (for Flutter Android)
1. Project Settings → General → **Add Android App**
2. Package name: `com.healthtrack.app` (match your `android/app/build.gradle`)
3. SHA-1: Get from `./gradlew signingReport` in android folder
4. Download `google-services.json` → place in `healthtrack_clean/android/app/`

### iOS App (optional)
1. Add iOS app with bundle ID
2. Download `GoogleService-Info.plist` → place in `healthtrack_clean/ios/Runner/`

## 4. Service Account (for Server Functions)

### Create Service Account
1. Project Settings → **Service accounts** → **Generate new private key**
2. Save as `firebase-service-account.json` (NEVER commit to git!)
3. Add to Netlify environment variables as `FIREBASE_SERVICE_ACCOUNT` (base64 encoded)

### For Local Development
```bash
export GOOGLE_APPLICATION_CREDENTIALS="/path/to/firebase-service-account.json"
```

## 6. Firebase Admin SDK Setup (Netlify Functions)

### Install Dependencies
```bash
cd netlify/functions
npm install firebase-admin
```

### Initialize in Function
```javascript
// netlify/functions/utils/firebase.js
const admin = require('firebase-admin');

if (!admin.apps.length) {
  const serviceAccount = JSON.parse(
    Buffer.from(process.env.FIREBASE_SERVICE_ACCOUNT_BASE64, 'base64').toString()
  );
  admin.initializeApp({
    credential: admin.credential.cert(serviceAccount),
    storageBucket: process.env.FIREBASE_STORAGE_BUCKET
  });
}

const db = admin.firestore();
const auth = admin.auth();
const messaging = admin.messaging();
const storage = admin.storage();

module.exports = { admin, db, auth, messaging, storage };
```

## 8. Authentication Custom Claims

For admin users and subscription tiers, set custom claims:

```javascript
// Netlify Function: setUserClaims.js
const { auth } = require('./utils/firebase');

exports.handler = async (event) => {
  const { uid, isAdmin, plan } = JSON.parse(event.body);

  const claims = {};
  if (isAdmin) claims.admin = true;
  if (plan) claims.plan = plan; // 'free' | 'premium' | 'family'

  await auth.setCustomUserClaims(uid, claims);
  return { statusCode: 200, body: 'Claims set' };
};
```

Then in Firestore rules:
```javascript
function isAdmin(userId) {
  return get(/databases/$(database)/documents/users/$(userId)).data.admin == true ||
         request.auth.token.admin == true;
}

function getUserPlan(userId) {
  return request.auth.token.plan ||
         get(/databases/$(database)/documents/users/$(userId)/subscription).data.plan;
}
```

## 9. FCM Setup for Push Notifications

### Server-side (Netlify Functions)
```javascript
const { messaging } = require('./utils/firebase');

async function sendPushNotification(userId, title, body, data = {}) {
  const userDoc = await db.collection('users').doc(userId).get();
  const fcmToken = userDoc.data()?.fcm_token;

  if (!fcmToken) return { success: false, reason: 'No FCM token' };

  const message = {
    token: fcmToken,
    notification: { title, body },
    data: { ...data, click_action: 'FLUTTER_NOTIFICATION_CLICK' },
    android: {
      priority: 'high',
      notification: { sound: 'default', channel_id: 'healthtrack' }
    },
    apns: {
      payload: { aps: { sound: 'default' } }
    }
  };

  try {
    await messaging.send(message);
    return { success: true };
  } catch (error) {
    if (error.code === 'messaging/registration-token-not-registered') {
      // Token invalid - remove from user doc
      await db.collection('users').doc(userId).update({ fcm_token: admin.firestore.FieldValue.delete() });
    }
    return { success: false, error: error.message };
  }
}
```

### Client-side (Flutter)
```dart
// In main.dart or notification_service.dart
FirebaseMessaging.onMessage.listen((RemoteMessage message) {
  // Show local notification
  showLocalNotification(message);
});

FirebaseMessaging.onMessageOpenedApp.listen((RemoteMessage message) {
  // Handle tap - navigate to relevant screen
  handleNotificationTap(message.data);
});

// Get token and send to server
final token = await FirebaseMessaging.instance.getToken();
await api.updateFcmToken(token);
```

## 10. Free Tier Limits & Costs

| Service | Free Tier | Notes |
|---------|-----------|-------|
| **Authentication** | 50K MAU | Email/password, Google, anonymous |
| **Firestore** | 1GB storage, 50K reads/day, 20K writes/day, 20K deletes/day | Sufficient for ~1000 active users |
| **Storage** | 5GB storage, 1GB/day download | For medical documents/photos |
| **Cloud Messaging** | Unlimited | Free push notifications |
| **Functions** | 2M invocations/month (Blaze required for external network) | Use Netlify Functions instead for server logic |
| **Hosting** | 10GB storage, 360MB/day | Optional - using Netlify instead |

### Cost Optimization Tips
1. **Use client-side queries** with pagination (limit 20-50)
2. **Cache aggressively** - use Flutter local SQLite for offline
3. **Batch writes** - use `WriteBatch` for multiple operations
4. **Composite indexes only where needed** - avoid over-indexing
5. **Offline persistence** - reduces reads significantly
6. **Use FlutterFire offline cache** - automatically caches recent data

### Estimated Costs at Scale
- 10,000 active users: ~$25-50/month (Blaze plan)
- 100,000 active users: ~$200-500/month
